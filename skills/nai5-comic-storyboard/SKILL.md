# 漫画架构与分镜

从用户的当前阶段开始：只要架构就交故事段落与揭示顺序；要拆页格就编排读者何时看见什么；要完整文字分镜才展开全稿；只改一格就处理该格及相关承接。四格默认 2×2、从左往右读（左上 → 右上 → 左下 → 右下），竖排等版式只在用户指定时用，不绑定固定节拍；既定读向、格数、服装、镜头和台词原文保留。

先读 [故事架构与导演](references/comic-story.md) 的本次相关部分。按任务选读：

- 页格、读向、破框、覆盖、气泡或条漫问题：读 [布局](references/comic-layout.md)。
- 续页、持物、服装、遮挡或明暗变化：读 [连续性](references/comic-continuity.md)。
- 某个镜头尚需具体构图：查 [画面构图](references/composition.md) 对应部分。
- 需要核查方法依据：读 [来源](references/sources.md)，不将归档资料当成本次看图或生图验证。

## 先导演，交完整文字分镜

完整新漫画、续写新页或未审阅的新增剧情，先交以下三部分，再接用户反馈。首次请求即使提到最终要 NAI 提示词，也不因此跳过分镜审阅；用户明确要求跳过时按其要求接续。请求里有「直接给词」「只要提示词」「不用分镜」「直接能用的」这类说法就算明确跳过，交给 `nai5-comic-writing` 在同一轮先出简稿、再转词。

- **剧情结构与必须保留的节点**：人物目标与关系、变化和落点、指定事件与文字。
- **建议总页数、分格数及每页核心内容**：在已定篇幅内安排节奏、重点和页尾承接。
- **完整逐页逐格文字分镜**：写全各格位置大小、景别视角、可见人物与动作、持续状态、文字归属及前后衔接；有覆盖画面时另列其范围、时刻和阅读位置。

没有剧本就先创作事件与必要对白，再安排读者何时获知信息，按节拍分配镜头和出场。让建立、动作、反应、停顿与揭示各有作用；结合格形、文字占位和连续状态反读整页。覆盖、破框和镜头变化服务剧情，不固定套版，也不用简短梗概代替完整分镜。只要架构或局部内容时仍交到本次范围。

## 按反馈接续写法

本次已请求后续转词时，确认后按确认版接 `nai5-writing` 与 `nai5-comic-writing`；收到明确可执行修改就落实后以修订版接续，无需额外再确认；范围外的连带改动仍先列出、不擅自改。仍在讨论、关键选择未定或只要看修订分镜时，继续停在分镜。已有定稿、已有确认或明确跳过审阅而要提示词时，直接带现稿转换；只改一格或一句按指定范围处理，不重新导演全篇。

构思时自由安排事件、演出、停顿和视觉形式，以当次意图决定详略；不用提示词长度、人数标签或 Character 框反向规定故事。开放创作时可主动为已有动作、环境和情绪安排合适的台词、旁白或声效，不必等用户逐字提供；原文冻结、忠实改编或静默格保留本次边界。需要新服装可接 `oc-costume-design` 后回当前阶段，已定衣服直接沿用。跨阶段通过已有产出衔接，不加载写法资源，不额外要求填写流程卡。
