# 服装设计

目标是设计属于本次角色和表达意图的服装。轮廓、结构、配色、材质与穿着状态共同表达身份、气质或纯粹的审美；日常可穿、舞台夸张和幻想造型可以有不同逻辑。不因现有标签库或后续实现难度缩窄创意。

<a id="costume-design.s01"></a>

### 日常构思方式

新服装、普通换装和开放式改稿都将[设计工具箱](#costume-design.s05)的方法纳入构思，无需等用户说“新奇一点”。读完角色与需求后，考虑哪些路径能表达本次核心印象，再比较少量有实质差异的方向，选定后细化轮廓、配色与部件。这是内部思考习惯，不要求每次输出方法表或多个方案。

方法可以单独使用，也可以自然组合；不要求每套设计混搭、加入道具、达到某个主题数量或用遍方法表。用户指定的风格、认可的部位和局部修改范围决定探索边界。已定设计不重新展开；要转成词句可直接接 `nai5-writing`。

<a id="costume-design.s02"></a>

### 建立设计简报

从当前用户资料、参考图和实际启用的 OC 资料提取相关约束；未知身份、性格与外貌不当作事实。设计所需但未锁定的部分可以提出明确主案，新增设计与用户设定分清：

- 身份：年龄感、职业/阵营、阶级、公开身份与真实身份。
- 性格：克制或张扬、亲近或疏离、整洁或随性、实用或仪式化。
- 世界：年代、地域、文化来源、科技/魔法水平、气候与资源。
- 场景：日常、工作、战斗、旅行、庆典、舞台或睡眠；需要完成哪些动作。
- 身体：身高比例，以及头发、手臂和腿脚会与帽兜、领口、袖口、手套、袜靴发生的可见关系；尾巴、翅膀、角、兽耳等幻想特征作为轮廓锚点记录。
- 识别锚点：主色、物种特征、标志图案、关键饰品、不可改变的角色设定。

把简报压成一句设计命题：

> 为【身份与性格】的角色，在【世界与场景】中设计【服装原型】，通过【轮廓/材质/图案】表达【核心印象】，同时满足【动作或身体约束】。

设计阶段以已有的固定外貌、体型、物种特征和识别锚点决定领口、头饰、配色与轮廓。OC 资料仅在用户提供或实际启用时使用；没有库时不阻塞，也不补造缺失外貌。只在帽兜、领口、袖口、手套、袜靴确实影响头发或四肢时处理穿着关系；默认不为翅膀、尾巴、角或兽耳补充开口、分片或防穿模结构。本阶段交服装设计，不默认附衣物提示词。设计定稿后若用户要文字表达，带着已有服装与本次终点接 `nai5-writing`。

<a id="costume-design.s03"></a>

### 按设计问题拆解参考

需要参考时，从能解决本次问题的来源取材，例如真实服装史或博物馆、当代服装/工装、动漫游戏角色或舞台服，不为凑来源数量扩展已定稿。把有用的参考按以下维度拆解：

1. 概念：身份、故事与情绪。
2. 轮廓：长短、宽窄、重心、外扩位置、露肤分布。
3. 色彩：主色、辅色、强调色，以及明度和冷暖关系。
4. 材质：硬/软、厚/薄、哑光/反光、挺括/垂坠。
5. 装饰：图案、滚边、褶、扣件、绳结、徽章、首饰。

要理解具体结构，可搜“时代/地区＋具体衣类”“职业＋制服”“动作需求＋防护/收纳”等能解释结构的资料。

<a id="costume-design.s04"></a>

### 先定轮廓和视觉层级

从[设计工具箱](#costume-design.s05)选择适合简报的方法，比较少量在轮廓、搭配关系、材质或穿法上有实质差异的方向，再选主案；数量随任务规模调整，明确的局部修改可直接处理。检查：

- 一眼可读的服装原型是什么：制服、礼服、工装、猎装、祭服、运动装、街头装等。
- 重心落在头肩、胸腰、胯部还是腿脚；宽窄变化是否呼应角色性格。
- 主形、次形、强调形是否形成清楚的面积与视线层级。
- 发型、耳角、尾翼与衣服是否争夺同一块轮廓空间。

<a id="costume-design.s05"></a>

### 灵活选择设计方法

以下方法用于日常构思，属于开放的工具箱，可独立使用或组合，没有优劣次序，也不要求逐项执行。优先从熟悉、容易辨认的形制和物件出发，让设计落在能画出的具体变化上。

| 方法 | 适合解决的设计问题 | 可见的操作示例 |
| --- | --- | --- |
| 服装与异质配件、道具搭配 | 服装本身已经成立，希望以直观反差建立身份或故事 | 普通雨衣配死神镰刀；街头装搭王冠与巨剑。各部件可以保留原本形制，协调比例、配色或携带关系即可成立。 |
| 跨风格单品组合 | 希望通过穿搭关系改变整体印象 | 复古衬衫、运动夹克与工装下装共同组成造型，用长短、松紧和色块关系协调。 |
| 剪裁与结构重组 | 希望主单品自身具有新的轮廓或结构 | 在连帽外套上借用水手领结构，把围裙的围裹方式用于外层裙片；保留清楚的主形制。 |
| 材质、工艺或功能转换 | 喜欢现有形制，希望改变它的触感、用途或身份感 | 以柔软针织制作有军装分割线的短外套；把礼服刺绣用在帆布工装口袋上。 |
| 比例与尺度变化 | 希望在较少部件中建立可爱感、力量感或重心 | 通过宽大上装与紧凑下装改变身形节奏；用小角色与大工具的尺度差形成反差。 |
| 穿法与场合错位 | 希望服装表达角色性格或生活习惯 | 正式衬衫卷袖并松开领口，制服外搭居家针织开衫；用穿着状态表现随性或亲近感。 |
| 图案与形状转译 | 希望角色母题进入衣服自身，而非只挂一个饰品 | 将兔耳形压缩为成对的长口袋盖，把花瓣节奏用于圆弧裙摆；保留少量可读特征。 |
| 单一风格内精炼与减法 | 风格已经合适，希望提升整体美感和辨识度 | 调整领口、衣长和色块面积，删去争抢焦点的挂饰，使一个已有轮廓更鲜明。 |

主题可以来自年代、职业、亚文化、生活场景或审美风格；数量、职责和影响范围保持开放。一个主题可以作用于多处，多个主题也可以作用于同一部件。整体搭配与部件内部融合都是有效做法，内部融合更深并不自动意味着设计更好。

例如“雨衣＋镰刀”的普通雨衣与熟悉武器可以直接成立。若本次设计需要，也可以进一步调整弧线或材质来呼应；这属于可选发展，不是合格前提。“街头装＋王冠＋巨剑”同样可以靠完整单品之间的气质与尺度反差成立，不必把王冠或剑的图案重复到每件衣物上。

选择时检查：本次角色印象由哪些可见变化表达；比例、色块、线条、材质或故事关系是否足以让组合协调；第一眼能否看清整体与焦点；增加或删减哪一项会实质改善画面。无需强求每个单品都有共同纹样或专门的连接细节。

例子用于说明方法，不作为以后换装的固定素材池。连续设计时，根据用户希望保留和改变的内容选择方法；用户要求新方向时，探索与上一套有实质差异的思路，已认可的方法与单品仍可使用。无需为轮换而改变成功选择。整体已经好看、贴合角色且满足本次变化需求时即可定稿。

<a id="costume-design.s06"></a>

### 组成一套服装系统

把部件放到身体上，说明彼此的层叠、长度与连接：

- 基础原型：决定第一印象的类别。
- 主角单品：承担最大辨识度的外套、裙装、胸甲、披肩或连体装。
- 支撑层：内搭、领口、袖型、腰封、下装和必要的过渡层。
- 腿脚系统：腿部露肤、袜/护具、鞋型与动作需求共同设计。
- 标志配件：按本次设计与用户清单保留包、帽、武器挂点或首饰，明确各自位置与视觉作用，不设配件配额。
- 开合与收纳：扣、拉链、系带、搭扣、口袋、挂环的位置需要说得通。

配色采用“主色＋辅色＋少量强调色”。标志母题可在领口、腰侧或鞋面等合适位置呼应，通过尺度或功能变化形成节奏，不要求填满位置或凑重复次数。

材质优先形成一组主要对比，例如硬皮革/软针织、哑光棉/亮面金属。例如硬皮革的边缘保持挺直，软针织在腰肘处聚褶，金属扣的亮点集中而棉布受光较柔；按材质调整具体部位。

细节数量不等于设计质量。主轮廓、层级和核心识别点成立后，先停下来检查整体；核心识别点可以来自服装结构、穿法、材质、图案、发饰、鞋袜或道具，不预设类别。新增装饰按轮廓、配色、母题或搭配效果取舍；用户明确要求的具体部件先保留，通过层级和位置协调，不以“过载”自行删掉。可爱感优先通过圆润轮廓、宽松与紧凑的比例、柔软边缘、清楚色块和少量易读图案表达，而不是继续叠荷叶边、扣件和挂饰。若要用巨大武器表现娇小反差，武器应明显大于角色但仍保留清楚的握柄、刃部或击发结构，避免大到像建筑或柱子。

<a id="costume-design.s07"></a>

### 让衣服表达身份、生活与表现逻辑

用可见证据表达身份，而不是只说“高级”“神秘”或“精致”：

- 阶级和资源：面料幅宽、刺绣密度、修补方式、金属件质量。
- 职业和习惯：磨损、污渍、卷袖、惯用侧口袋、工具挂点。
- 气候和活动：通风、保暖、防水、活动量、坐骑或战斗需求。
- 穿着关系：说明长发如何位于帽兜或衣领内外，宽袖是否妨碍手部动作，手套、袜子和鞋靴怎样衔接。幻想附肢默认遵循二次元视觉逻辑，不主动为翅膀、尾巴、角或兽耳添加洞口、分片、系带或加固边；只有用户把接口本身设为可见设计重点时才展开。

“舞台装/战斗装看起来合理”和“日常能穿”是不同目标；根据场景选择，不必把所有设计都合理化成现代日常服。

<a id="costume-design.s08"></a>

### 设计换装与角色衣橱

先区分不变量和变量：

- 不变量：角色配色、物种特征、标志母题、关键饰品、某种固定线条或开口语言。
- 变量：服装原型、季节、场合、裙裤比例、材质、外套长度、正式度。

保留用户要求与角色辨识所需的锚点，变化幅度由本次任务决定。主题完全不同的换装应呈现清楚的新印象；同系列衣橱可以延续版型与母题；配色变体或局部精修也可以是完整的设计目标。根据目标判断变化是否有效，不规定每套必须保留或改变多少项。

<a id="costume-design.s09"></a>

### 根据出图反馈迭代

先把用户给出的图与对应设计稿对照。设计本身满足要求而图没表现出来，属于实现或写法问题，不因此自动重设计；用户要调整设计时再判断是哪一层：

1. **轮廓不对：** 先调整量感、长度与分割，或更换基础服装原型；根据用户认可的部分选择改动幅度。用户喜欢的原型可以保留，并用[设计工具箱](#costume-design.s05)的其他方法发展。
2. **气质不对：** “可爱”被硬质棱角、笔直分割和沉重配件压住时，先改主轮廓、边缘形状与比例。
3. **道具读错：** 弩炮变成柱子、复杂机关无法辨认时，改用更简单的标志性几何，或直接换成另一类道具；不要持续堆结构词。
4. **携带关系不对：** 包、剑、镰刀等位置错误时，明确写肩扛、斜背、手持及左右侧，写清接触点和携带方向，例如背带斜跨胸口、包落在左胯，或握柄靠右肩、刃部朝身后。
5. **主题仍然普通：** 回到[设计工具箱](#costume-design.s05)，选择能改变第一印象的方法。可以保留服装而换用异质配件或道具，也可以调整单品组合、结构、材质、比例、穿法或母题；不预先固定改哪个部位，也不要求增加主题数量。

保留用户明确认可的部分，只替换导致失败的层级。按本次反馈确定改动范围，例如服装原型、轮廓重心、主题语汇的落点或核心识别点；用户允许调整的复杂部件可简化或替换；锁定部件先修表达、位置或可见关系，需要改设计本身时提出具体替代建议，不把局改扩成删件。没有实际图像反馈时不宣称已验证生成效果。

<a id="costume-design.s10"></a>

### 理解既有偏好并判断是否需要变化

角色库记录过去采用的造型。蝴蝶结、蕾丝、短裙、袜类、制服感等元素反复出现，可能与用户偏好、角色设定或既有生成方式有关；频率本身不能判断设计质量，也不足以认定这是需要纠正的惯性。当前要求、参考图和用户明确反馈优先于从频率推测出的偏好。

- **允许有价值的重复。** 熟悉的单品和组合可以维持审美连续性与角色辨识度。同样的“百褶裙＋长袜＋玛丽珍鞋”可以通过比例、配色、穿法和搭配形成适合不同角色的结果；整体成立时可以直接采用。
- **根据具体问题调整。** 需要警惕的是忽略当前需求的自动套用，例如不同性格与场合仍得到同一种气质，或用户明确要求的新印象始终没有出现。先定位不匹配的部位或关系，再选择修改方法，不将原因直接归结为某一服装类别。
- **扩展选择范围，保留取舍自由。** 裤装、裙装、连体装、不同鞋型等都属于候选。按轮廓、角色气质、色彩、搭配关系和用户意图取舍，不设品类配额，不因少见而优先，也不因常见而排除。需要新意时，可以从熟悉元素中继续发展。
- **承认纯审美的理由。** 不对称、系带、蝴蝶结等可以通过视觉平衡、节奏、垂坠或俏皮感成立，无需一律赋予实用功能。根据它在整体中的可见效果判断保留、调整或删减。

这些判断融入日常构思，不要求逐件向用户论证。目标是让每次选择回应当前设计，而非追求衣橱统计上的均衡或最大差异。

### 交付格式

按用户要求的详略交一个主案或所需方案，以下为可选组织项，已有答案不重复确认；不机械填空、补背景故事或附提示词。只改某部件时仅交该部件。

```text
设计命题：
角色识别锚点：
服装原型与场景：
轮廓与重心：
配色层级：
单品拆解：
材质与褶皱：
母题与配件：
开合、收纳与头发/四肢关系：
可见的角色故事：
变体建议：
刻意避免：
```

需要验证整套服装时可从正面、背面、侧面与动作状态观察；只要局部设计时检查相关部分即可：轮廓是否仍可读，衣服如何穿脱，头发是否被帽兜或衣领意外吞没，袖口和鞋袜是否妨碍四肢，装饰是否掩盖视觉焦点。翅膀、尾巴、角和兽耳只检查是否保留角色辨识度，不补写穿模解决方案。
