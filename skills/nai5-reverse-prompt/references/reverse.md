# 照图反推提示词

用户发来一张图，要照它写一版能直接用的 NAI V5 提示词，或只要其中一部分时用本文件。只问「画面里有什么」、不要提示词时，不按本文件交付。语法、字段、质量与 UC 一律按 “写法规范与交付边界”（`nai5-writing`：`references/conventions.md#writing-conventions`），本文件只管看图、取舍和写到哪。

<a id="reverse.s01"></a>

## 三种来源，回复里分开标

- **原文**：图里带的真提示词（元数据）。有原文时先说「这张图带原文」，默认给原文或照原文改（原文里的 UC 用户要才给，原文带的质量词照留并提醒关开关）；用户明确要看图反推（比如想对照）时才推。原文按 “用户事实、原串与本次可见范围”（`nai5-writing`：`references/conventions.md#shared-facts`）保留。
- **用户给的**：用户说了是谁、要什么风格、要保留什么。
- **推测**：这次看图推出来的。推测不能说成原文。

**用户要求先看图反推、再与原文对照时**：先只读取图片，写出并保留反推稿，再展开元数据原文逐项比较。选图时可以确认是否带元数据，但原提示词、自动识别标签和既有反推文本留到初稿完成后再读。对照后的改稿另列，保留对照前的版本。若已经提前读过原文，说明这份稿参考过原文，不再称为独立盲推；普通提取原文或照原文改写仍按上面的来源规则处理。

<a id="reverse.s02"></a>

## 范围：用户要什么就推什么

用户可以只要一部分：构图与镜头、光影、配色、服装、发型与外貌、姿势动作、表情、场景、人物关系、画面里的文字、版式。只推那部分，写进它在字段里该在的位置（主串的一段或某个角色栏的一段）；用户已有的其他内容不动，按 “精确修改与保行为”（`nai5-writing`：`references/conventions.md#writing-exact-edit`）处理。

用户没说范围，就推整张：主串加每人一个角色栏。

<a id="reverse.s03"></a>

## 动笔前读语法

从 `nai5-writing` 读：

1. `SKILL.md`；
2. “字段职责：先选画面类型”（`nai5-writing`：`references/conventions.md#field-contract`）；
3. “普通插画完整模板与落笔检查”（`nai5-writing`：`references/illustration.md#general-writing.s02`）；
4. 两人以上再读 “多人交互：先定施受，再找锚点”（`nai5-writing`：`references/illustration.md#general-writing.s06.h13`）开头那段和 “表达已确定的参与关系”（`nai5-writing`：`references/illustration.md#general-writing.s06.h14`）；用户要写细或分开写时，再读到 “前缀的使用情形”（`nai5-writing`：`references/illustration.md#general-writing.s06.h18`）。

只推局部时按范围读对应小节，不整本读。图是漫画或分格时，逐格写法另接 `nai5-comic-writing`。

<a id="reverse.s04"></a>

## 看图

1. 把可见内容按下表分到待写字段，再组织语言；只推局部时仅提取请求范围。

   | 观察内容 | 普通插画的落点 |
   | --- | --- |
   | 人数、持握物、身体支撑物、形成边框或遮挡的实体 | 主串前部的独立词组；物件的数量与形态随词组保留 |
   | 姿势、头部朝向、视线、嘴部状态与表情 | 主串的姿势和表情词组；两个人以上时不写进前两行，按人写在主串里各人那行 `Character N:` |
   | 取景范围、透视、场景、光与色 | 主串的镜头及环境部分 |
   | 接触、前后遮挡、相对位置与大小、文字和载体 | 主串的关系句；先有物件词组，再说明关系；两个人以上时人物的位置和关系只写一两句（谁在左右、谁对谁做什么），文字和载体、遮挡照常写 |
   | 每个人的性别、稳定外貌、服装与配饰 | 对应各人的角色栏（栏名 `Character N:` 写在代码块上面，性别外貌一行、服装一行），两个人以上时从看画的人这边看从左往右编号，最左边的是 `Character 1`；用户说要把动作分开写进角色栏时另按共同写法 |

2. 用可见关系描述动作（两个人以上时人物的动作按上表写在各人那行 `Character N:`，句子简单写，手部细节用户要写细再补）：手从画面的哪一边进入、接触谁的哪个部位，前景遮住哪里，人物与物件的大小如何对照。判断手部朝向时，先核对镜头看见的是哪一面：指甲与指背关节、掌纹与掌心轮廓分别提供手背或手掌的依据；再写朝向和伸向。袖口、裁切或透视遮住这些依据时，只写能确认的轮廓、伸向与遮挡。作品背景或画外设定不从图中补出。
3. 镜头高度与人物低头、抬头或视线方向分别判断。先检查能看到物体的顶面还是底面、身体透视与地平线等线索；近大远小只说明距离与透视，不能单独确定仰拍或俯拍。线索不足或相互冲突时，提示词只保留能确认的取景和前后关系，高度的不确定性留在附注。
4. 遮挡、模糊或裁切导致看不清时，保留能确认的轮廓与关系，记下具体缺口，在交付时说明。
5. 按表逐字段写完，再用原图核对：每个方向判断能指向相应的可见依据；表情仍在主串，外貌衣物在对应角色栏，决定遮挡或取景的实体既有名称也有关系。人物在画面里的站位写进主串的关系句。附注中标为看不清或无法确定的细节，在提示词里也保持未定，不一边说明存疑一边指定它。

<a id="reverse.s05"></a>

## 不从画面推的

- **画师串和画风**：不从画面推画师名。画师串的位置留独立一行 `<画师串：自己贴>`，或请用户从自己的串里选。用户给了风格描述再写风格。
- **质量词**：不从画面推，默认不写，用户要才写，原文里本来有的照留；也不因为画得好就加高完成度词；画面有字时按 “完整导出的质量词与 UC”（`nai5-writing`：`references/conventions.md#shared-quality`）提醒用户关掉官网的质量词开关。
- **UC**：不从画面推，用户要 UC 才给。要了就沿用用户自己的 UC（当前环境能取到就用工具取），没有就用基础串；只删和这张图冲突的项（多人图删 `extra characters`、画面有字时不压字之类），不往里加从画面推出来的排除项。
- **负权重**：不从画面推。用户明确说这张不要什么，才按规矩写成主串最后的负权重行。
- **角色是谁**：不凭长相认人。用户说了是哪个 OC，就按用户给的或实际启用的 OC 资料写外貌和服装；像版权角色也先问用户，确认了再写名字，没确认就只描述外貌。未确认的名字会额外触发身份设定，因此身份确认前保留可见外貌描述。
- **自动识别标签**：不拿 tagger 的结果当角色依据。
- **角色位置**：普通插画和多人图不给界面的角色位置，由用户自己定（“字段职责：先选画面类型”（`nai5-writing`：`references/conventions.md#field-contract`））；站位写进主串的关系句。

<a id="reverse.s06"></a>

## 交付

下列分工是本技能新写普通完整提示词的输出约定，不表示 NAI 角色栏无法容纳动作或文字。用户已有原串只做局改时，保留原有字段分工，按指定范围修改，不借反推重排其他内容。

- 推整张时按 `nai5-writing` 的完整导出依次交付各字段，每个字段独立代码块，栏名带冒号写在代码块上面、不放进代码块，说明放在最后的 `补充:` 下面；主串写完并关闭代码块后，再开始角色栏：
  - 主串（Base Prompt）：人数、镜头与构图、场景、光与色、动作、表情及人物之间的关系句；两个人以上时前两行不写动作、姿势、表情和视线词，按人写在主串最后各人那行 `Character N:`（先写性别词），关系句简单写；不写质量词；
  - 每人一个角色栏（Character 1:、Character 2:……）：只写性别、外貌与服装（分两行），两个人以上时从左往右编号；用户说要把动作分开写进角色栏时，主串不写各人那行 `Character N:`，各人的动作另起一行写在自己那一栏最后，表情和视线跟着写进去，按普通写法的多人交互处理；
  - Undesired Content：用户要 UC 时才给，放在最后一块，用户的或基础串，只删冲突项。
- 只推局部时只交那一段，说明它放在哪个字段的哪个位置。
- 代码块外用几行说明：哪些是看见后写的，哪些是推测，哪些留空等用户补（画师串、角色名、看不清的地方）。
- 有写入工具且用户要求填工作台时，写完用工具读回核对一遍；没有写入工具就只交文本，如实说明未写入。
