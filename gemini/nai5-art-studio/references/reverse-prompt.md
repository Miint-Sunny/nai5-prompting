# 照图反推提示词：来源区分、视觉观察与字段落点

本文件用于用户发来一张参考图片，要求照图反推一版可直接使用的 NAI Diffusion V5 提示词（或只反推其中某个局部，如构图、光影、服装、动作）。若用户只是问“画面里有什么”、不需要提示词，直接按普通问答回答即可。

反推提示词的语法、字段分工、质量词与 UC 规则遵循 [提示词写法总纲](writing-core.md#writing-core) 与 [普通插画写法](writing-illustration.md#writing-illustration)（漫画或分格图另接 [漫画分格写法](writing-comic.md#writing-comics)）。

---

<a id="reverse.s01"></a>

## 1. 三种信息来源必须在回复中分开标明

在代码块外的简短附注中，清晰区分以下三种来源，**绝不把看图推测说成原图元数据**：

1. **原文（元数据）**：
   - 图片本身携带的真实生成元数据（如 NAI PNG Info / Comment）。
   - 若当前环境能读到图片元数据，先告知用户「这张图带原文」，默认直接提供原文或照原文修改（原文里的质量词保留并提醒关官网开关；原文里的 UC 仅在用户索要时附上）。
   - **盲推对照流程**：若用户要求“先看图盲推，再与原文对照”，先只观察画面写出并保留盲推初稿，再读取元数据原文逐项对比，将对照后的改稿另列，不覆盖盲推初稿。
2. **用户给的事实**：
   - 用户明确告知的角色身份（如指定某个 OC）、指定画风或要求保留/修改的要素。
3. **看图推测**：
   - 本次通过观察画面内容反推出来的提示词。

## 2. 反推范围：按需提取

- **整张反推（用户未限定范围时）**：输出完整 `Base Prompt:` + 每名可识别角色一个 `Character N:` 栏（用户索要 UC 时再加 `Undesired Content:`）。
- **局部反推（用户指定只推某一部分时）**：
  - 用户可以只要构图与镜头、光影与配色、服装、发型与外貌、姿势动作、表情、场景、人物关系或画面文字。
  - **只输出用户索要的那一段提示词**，并说明它应当放进哪个字段的哪个位置（例如放入 `Base Prompt:` 的镜头环境行，或放入 `Character 1:` 的服装行）；用户已有的其他原串内容保持不动。

## 3. 画面观察与字段落点

动笔前先观察画面可见内容，按下表分配到对应字段：

| 观察内容 | 普通插画中的字段落点 |
| --- | --- |
| **人数、手持物、身体支撑物（椅、桌面、栏杆）、前景遮挡实体** | `Base Prompt:` 前部的独立词组（物件的数量与形态随词组保留） |
| **姿势、头部朝向、视线、嘴部状态与表情** | 单人图放入 `Base Prompt:` 前两行的姿势与表情词组；**两人以上时前两行不写动作、姿势、表情和视线词**，按人写进 `Base Prompt:` 末尾各自的 `Character N:` 动作行 |
| **取景范围、透视、场景、时间、光影与色调** | `Base Prompt:` 的镜头及环境行 |
| **接触、前后遮挡、相对站位与大小对照、画面文字与载体** | `Base Prompt:` 的自然语言关系句；先有物件词组，再写关系句；两人以上时人物站位与互动关系只写一两句（谁在左谁在右、谁对谁做什么） |
| **每个人的性别、稳定外貌、服装与配饰** | 对应各人的 `Character N:` 栏（性别与外貌一行、服装与配饰一行）；**两人以上时从观者视角从左往右编号，最左边的人是 `Character 1`** |

### 关键视觉判断准则
1. **手部朝向与掌背核对**：
   - 判断手掌朝向镜头还是手背朝向镜头时，**先核对画面可见依据**：能看见指甲与指背关节的是手背，能看见掌纹、掌心凹陷与拇指根部肉垫的是手掌。
   - 确认手背/手掌后再写手部朝向、从画面哪一侧伸入、接触哪个部位。若被袖口、前景或裁切遮住，只写能确认的轮廓、伸向与遮挡。
2. **镜头俯仰高度 vs. 人物抬头/低头**：
   - 镜头机位高低（`high angle` / `low angle`）与人物头部俯仰（`head tilt` / `looking up` / `looking down`）必须分开判断。
   - 先检查场景物体的顶面/底面可见性、身体透视压缩与地平线位置；单纯的“近大远小”（如手伸向镜头显得大）只说明透视距离（`foreshortening`），不能单独证明仰拍或俯拍。
   - 线索不足时，提示词只保留能确认的取景和前后关系，机位高度的不确定性写在代码块外的 `补充:` 说明里。
3. **遮挡与看不清的部位**：
   - 被遮挡、模糊或裁切出画的部位，只写能确认的可见部分；在 `补充:` 中标明看不清或存疑的缺口，**切勿一边在附注里说“看不清鞋型”，一边在提示词里硬编一双具体靴子**。

## 4. 绝不从画面硬推的 7 类内容

1. **画师串（Artist tags）**：不从画面猜测画师名。画师串位置留独立一行 `<画师串：自己贴>`，或按用户提供的画师串填入；用户给了风格描述时只写通用风格词。
2. **质量词**：不从画面反推质量词，也不因为原图画得精致就自行添加 `masterpiece, best quality`；画面含需保留的文字时，提醒用户关掉官网质量词开关。
3. **`Undesired Content`（UC）**：不从画面反推排除词。仅在用户索要 UC 时提供基础串（删去与该图冲突的项，如多人图删 `extra characters`、有字图删 `logo`）。
4. **负权重行**：不从画面推测负权重；仅在用户明确要求“这张图不要某某元素”时写成主串末尾的负权重行。
5. **未确认的角色身份名**：不凭长相给角色贴 OC 名或未确认的版权角色标签（未经确认的角色标签会触发模型自带的额外身份设定）。若疑似某知名版权角色，先在 `补充:` 中询问用户是否启用该角色名，初稿仍用可见外貌描述。
6. **自动打标器（Tagger）噪声**：不把第三方打标器的机器识别标签直接当作真实设定依据。
7. **普通插画的界面角色位置坐标**：普通插画和多人图不输出前端 `Character Positions` 坐标，人物左右站位直接写进 `Base Prompt:` 的关系句。

## 5. 交付格式检查

1. **整张反推**：依次输出 `Base Prompt:`、`Character 1:`（、`Character 2:`……），每个字段独立一个代码块，栏名带英文冒号写在代码块外上方，代码块内不写栏名。
2. **`补充:` 附注**：放在所有代码块下方，简明列出：
   - 哪些是直接观察画面写出的核心事实；
   - 哪些属于受遮挡/透视限制的推测；
   - 哪些留空等待用户补充（如 `<画师串：自己贴>`、角色身份名、被遮挡的下半身服装）。
