# 通用写法（基准规范）

> **公开版**：群成员网名已匿名化为「作者A/B/…」。文中引用的「群偏好」池子、
> 「群频次表」和「个人-X」skill 属于内部偏移层，本包不含——
> 遇到这类引用忽略即可，按常识取材。

把一张想好的「分镜」写成 V5 提示词的**默认规则**——字段怎么分、块怎么排、
哪块用词组、哪块用句子、多人怎么绑。依据是 957 条真提示词的统计 + 出图实测。
用动画制作的话说：`通用构思` 是**会议桌**——编剧/监督/原画/摄影四个岗位在那边
把决定做掉、出分镜表；本篇是**作画桌**——先认画材与规格（开篇语法节），
再按分镜表落笔（各岗位决定的落笔归宿见构思文末的对照表），
手边一册作画参考（§10 判据实测）。

**优先级，冲突时从上往下**：

1. **运行环境注入的 NOTE**（语法与能力边界）
2. **当前 active 作者的写法层**（作者B 的负权重、作者A 的 XML 分块——
   切到谁就按谁的方言写）
3. **本篇**（谁都没说话时的默认）

构思（画什么、补多少、分镜怎么定）不在这里，在「通用构思」。

## 语法与能力边界（画材与规格：引擎认什么）

> 扩展环境里这一层由运行时 NOTE 注入**摘要版**、冲突时以 NOTE 为准（优先级第 1 条）；
> 本节是**详版**（1918 张口径实测），供无运行时的环境和查证用。
> 语法 = 引擎认什么（合法性）；本篇其余各章 = 其上怎么组织才稳（有效性）。

### 权重

| 写法 | 效果 |
|---|---|
| `1.2::tag::` | 增强，作用到 `::` 结束 |
| `0.5::tag::` | 弱化（0–1 区间） |
| `-2::tag::` | 负权重，定向移除或概念反转 |
| `{tag}` / `[tag]` | 旧语法，只在读旧串时理解，自己写用数值 |

实测档位：增强 1.2 / 1.25 / 1.3 / 1.5 / 2；弱化 0.4–0.8；负权重 -1 / -2 / -3 / -5。

**默认不加权。** 只在实测某层效果不足时才对该层加权，不为加权而加权。

负权重的两种用法：
- **定向移除**：`-1::hat::`，不足时加深到 -3
- **概念反转**：白背景虚空 `-1::simple background::`；画面缺色 `-1::monochrome::`

`::` 可以闭合任何未配平的 `{` `[`。

### 分段

**空行分段是主流**（实测 74%），段数中位 3。一段一个职能。

XML 式分块（`<artist>` / `<style>` / `<artwork>`）实测 47% 的人用，
但那是这个群从 V4.5 带来的习惯，**官方示例一条都没用**。自己写不必用（详见 §0.2）。

管道符 `|` 分段：实测 957 条里只有 8 条用过，**不建议**。

### 文字渲染

用**引号**包裹要渲染的文字，前端会自动生成 `Text:` 块。
手动写 `Text:` 块会关闭这个自动功能。

样式和位置用自然语言描述：

> A handwritten speech bubble with green text and a white background, floating next to
> the purple haired girl's head, "Hello, world!"

支持英语、日语、中文。V5 相比 V4.5 可渲染文字长度大幅增加。

**反过来也成立：不想画文字就别用引号**——叙事句整段包引号会被当成要渲染的
文字（§0 常见错 6、§4.8）。

### 语言

官方一级支持**英语和日语**。中文、德语、西班牙语、葡萄牙语实测可用，
但**非训练重点，效果会打折**。

实测群里 18% 的提示词含中文，官方示例里也有整条中文和整条日文的。
**建议**：主体和技法用英文最稳；确实要中文语感（成语、古风词）时局部用中文。

### 多角色（语法侧）

- V5 支持最多 22 个角色同框，用画布自由定位（在 output viewer 里直接摆）
- prompt 内的角色编号/顺序要跟画布定位对应
- 角色栏只写外貌服装，**不写动作、场景、环境**
- 复杂互动（多人、动作纠缠、道具交换）用分段模式写死归属
- 串味处理：句子里写死归属 + 该角色 UC 栏排除对方特征 + 检查人数 tag 没在角色栏重复

### 漫画（语法侧）

**V5 能一次生成整页多格漫画**，不再限 2koma，不用切图拼接。
格数 tag 当锚点，**分镜内容用自然语言逐格描述**：

```
4koma, comic, speech bubble, emphasis lines, 1girl, school uniform.
The page reads top to bottom in four equal panels.
Panel 1: she is asleep at the desk, cheek flattened against an open book.
Panel 2: the alarm goes off; she jolts upright, hair sticking out, eyes still shut.
Panel 3: close on her face as she registers the time, mouth open, sweat drop.
Panel 4: she is already gone — only the toppled chair and a slice of toast in mid-air remain.
```

### V5 开关与旧限制（NOTE 没细说的三条）

- V5 新增 tag：`depthness` · `attractive male` · `low/medium/high/ultra complexity` · `has alpha`——
  只在跟画面直接相关时用，不当固定质量尾
- 透明两分法：整图透明背景 → `transparent background` + `has alpha`（不够时 `2.1::…::`）；
  物体半透明但背景保留 → `alpha transparency` + `has alpha`
- 不要沿用 V4 文档「最多六人」和 5×5 网格旧限制

## 0. 输出长什么样

NAI 的输入是**几个独立字段**，不是一段文本。产出时按字段给，不要合成一坨：

| 字段 | 装什么 |
|---|---|
| **主提示词** | 画师串 · 人数 · **动作 · 表情 · 镜头 · 场景 · 背景** · 光影 · 氛围色彩 · 技法 · 质量尾 |
| **Character 1/2… Prompt**（角色栏） | **只放外貌**：发型 · 眼睛 · 身体特征 · 服装 · 配饰 · 角色名与作品名 |
| **Undesired Content（UC）** | 这张图明确不要的东西 |
| 参数 | 仅在用户问起或排查时给 |

> 这条分工不是本文的发明，运行环境已经规定了：
> **「角色栏只放外貌、发型、眼睛、身体特征、服装和配饰；
> 动作、表情、镜头、场景、背景一律留在主提示词里，不要漏进角色栏。」**
> 下面 §0.1 的实测数字是佐证，不是另一套标准。

**按这个格式回复**（运行环境不规定回复格式，所以由这里定死；用户要改格式听用户的）：

```
Prompt:
1girl, solo,                    ← 人数放最前，只写一次
<镜头 · 动作 · 表情 · 场景 · 背景 · 光影 · 氛围色彩>
                                ← 这一段里**一个发型/眼睛/服装/配饰的词都不写**，
                                  它们全在下面的角色栏。写了就是重复。
<句子段：空间关系 / 占画幅 / 进行中的动作 / 光影叙事>
                                ← 句子直接写，**不加引号**（引号=要画进图的文字）
                                ← 多角色时在这里用 Character 1 / Character 2 写死归属，
                                  编号跟角色栏一致，不要写 A/B
<技法词>, <质量词>              ← 质量词是整条的最后一行，写在所有句子之后

Character 1:
<发型 · 眼睛 · 体征 · 服装 · 配饰>   ← 用 girl / boy，不带数字
                                  ← 不写动作/表情/镜头/场景/背景

# 但角色是**具名版权角色**时，这一格短得多——名字自带全套设定：
Character 1:
<角色名, 作品名, girl / boy / other>  ← 性别词跟着这个角色本身，别默认 girl
                                  ← 没换装就到此为止，别再列发色/发型/眼睛（§3.7）
<换装时才加：一个成套的服装说法>       ← 如 swimsuit / casual clothes，不拆成领子裙子丝带

UC:
<这张图明确不要的东西；没有特别要排除的就写「用默认预设」>
```

**字段名一律用半角冒号 `:`，不要用全角的 `：`。** 字段名本身也用英文
（`Prompt` / `Character 1` / `UC`），跟 NAI 界面上的叫法一致。

**写这个模板时最容易犯的六个错（1–4 按实测频率排，5–6 是下游实测新收）：**

1. **外貌在两边各写一遍。** 角色栏是把外貌**搬过去**，不是抄一份。
   写了角色栏之后，**主提示词里不该再出现任何发型 / 眼睛 / 服装 / 配饰 / 角色名的词**。

   ❌ 主提示词 `1girl, solo, silver hair, ahoge, white dress, from below`
      ＋ Character 1 `silver hair, ahoge, white dress`
      → 外貌词重复，角色栏没起作用，反而把这些特征的权重翻倍
   ✅ 主提示词 `1girl, solo, from below, snowy plains, backlighting, looking at viewer`
      ＋ Character 1 `silver hair, long hair, ahoge, white dress, frills, white gloves`

2. **质量词收在第一段 tag 的尾巴上**，后面还有几段句子。
   它该在**整条的最末尾**——332 条含长句的真提示词里，最后一次质量词的位置
   中位就在整条末尾（79% 落在最后 30% 内）。

3. **反向漏**：动作、表情、镜头、场景、背景漏进角色栏。它们一律留在主提示词。

4. **具名角色还把外观列一遍。** 上面模板的第一种写法是给原创角色的；
   版权角色用第二种。**人越多越容易犯**——实测五人图里五格全部多写了发色发型
   （同一个模型写四人图时一格都没多写）。名字已经带了设计，多写只会跟它打架。

5. **人数写串**（下游实测两种真翻车样子）：主提示词写了 `2girls`，
   角色栏又各写一个 `1girl`，拼起来就是 `2girls, 1girl, 1girl`；
   或者 `2girls, solo,` 同写——直接自相矛盾。规则重复一遍：
   **人数 tag 只在主提示词最前面出现一次**，角色栏只写不带数字的 `girl`/`boy`；
   `solo` 只配单人。

6. **叙事句包双引号**（同为下游实测）：明明不是对话也把整段句子括进 `"…"`——
   引号在语法层的含义是**要画进图里的文字**（见开篇「文字渲染」），
   模型可能真把句子当字画出来。句子直接写；只有确实要画对话气泡/字条时才用引号。

**画师串一行只有两种来源：用户给的，或个人偏移【完全模仿】节里查表抄的固定串。**
两者都没有就写一行 `<画师串：自己贴>` 占位或干脆省略（没串也能出图）——
**不要自己编**：偏移里的班底/频次表是画像不是配方，攒出来的串不是任何人的。

**只给结果，不要附「生成方式说明」这类解说段落**——
运行环境已规定「最终回复直接给结果，不要复述流程」。用户问起来再解释。

**单人且外貌简单时可以不写角色栏**，把外貌直接写进主提示词、按 §0.3 的顺序放在人数后面
——作者B 90% 的图、作者A 94% 的图都是这么写的。
一旦有两个及以上角色，角色栏是防串色的主要手段，必须分开写。

**人数上限不用担心**：V5 的角色栏防串色能力很强，社区有人试到 **22 个角色**仍然不串。
所以多人场景该拆几个就拆几个，**不要为了省事把两个人合并进一个角色栏**——
那才是串色的来源。旧文档里「最多六人」「5×5 网格」那套是 V4 的限制，已经不适用。

> 前端扩展的**快捷填入**一次只处理 6 格（`AGENT_MAX_CHARACTER_SLOTS = 6`）。
> 那是填表的限制，不是模型的限制——**超过 6 个照写**，多出来的用户手动贴。
> 别因为这个把角色合并。

### 0.1 角色外貌走角色栏，不要写进主提示词

957 条真提示词里 **445 条（46%）用了角色栏**。用了的那些，外貌类词就明显搬了过去：

| 类别 | 出现在主提示词 | 出现在角色栏 |
|---|---|---|
| 发型发色 | 9% | **52%** |
| 眼睛 | 27% | **52%** |
| 服装 | 30% | **56%** |
| 体征 | 54% | **63%** |
| 角色名 / 作品名 | 2% | **32%** |
| 画师串 | **96%** | 0% |
| 技法词 | **73%** | 3% |
| 人数 | **61%** | 12% |
| 背景 | **43%** | 5% |
| 场景 | **37%** | 23% |

配饰两边都常见（主 21% / 角色栏 31%），按它属于谁来放。

**实测里有一处跟规定不一致**：34% 的角色栏写了表情词。
那是群里的写法偏差，**不是该照做的**——表情留在主提示词。

**角色栏里的人数词不带数字**：写 `girl` / `boy`，不写 `1girl`。
`1girl` / `2girls` 只在主提示词最前面出现一次。

**多角色时这条是必须的**，不是可选：外貌全堆在主提示词里，模型分不清哪件衣服属于谁。

> 46% 这个数字按人差别极大：作者C 98% · 8.25 批 88% · 作者F 77% · 杂池 68% ·
> 作者D 11% · 作者B 10% · 作者A 6%。
> **所以「群里都用角色栏」是不成立的**——单人图不少人全写在主提示词里。
> 但一旦超过一个角色，用角色栏是分工最干净的做法。

### 0.2 XML 块是这个群的人工约定，不是 NAI 语法

真提示词里常见的开标签只有三个：

| 标签 | 条数 | 占比 |
|---|---|---|
| `<artist>` | 441 | 46.1% |
| `<style>` | 321 | 33.5% |
| `<artwork>` | 20 | 2.1% |

（另有一位作者自用的一组 `<identity>` `<hair_architecture>` `<attire_and_materials>`
`<color_system>`，各 14 条——个人方言，不要照抄。）

**三件必须说清楚的事**：

1. **NAI 不解析这些标签。** 官方 12 条示例**一个 XML 块都没用**；
   前端扩展也没有把它们当语法处理。它们是群里的人**给自己看**的分隔符，
   对模型来说就是几个多余 token。
2. **所以它不是规则。** 采用率不到一半，作者B 和作者D一次都没用过。
   用户没要求就不必加；照着某个人的写法走时再按他的习惯加。
3. **不要自造标签。** `<content>` / `<scene>` 在 957 条里**出现 0 次**（`<quality>` 仅 1 条），
   是模型从 `<artist>`/`<style>` 外推出来的。加了不会被解析，
   只是往提示词里塞噪声。**质量词直接写在主提示词末尾**，不要包块。

用的时候只用这两个，且只包它们本来的内容：
`<artist>` 里放画师串，`<style>` 里放技法/画风词。

### 0.3 主提示词里的顺序

实测 957 条的两两先后（数字是「A 排在 B 前面」的比例，n 见括号；
`core/corpus_stats.py` 可复跑）：

```
人数 →  外貌  →  服装  →  表情  →  镜头  →  动作
      发型/体征/眼睛                    ↑
                          场景 · 背景 ──┘（在镜头之前）
                                              质量尾 → 最后
```

| 对 | 比例 | n |
|---|---|---|
| 人数 → 发型 | 85% | 298 |
| 人数 → 服装 | 85% | 347 |
| 发型 → 眼睛 | 86% | 310 |
| 体征 → 服装 | 78% | 416 |
| 服装 → 表情 | 61% | 359 |
| 服装 → 镜头 | 58% | 387 |
| 表情 → 动作 | 70% | 343 |
| 场景 → 镜头 | 53% | 401 |
| 场景 → 动作 | 63% | 311 |
| 镜头 → 动作 | 63% | 384 |
| 技法 → 质量尾 | 76% | 723 |

**人数放最前、质量尾放最后**这两条最硬（人数领先外貌/服装/表情/动作/镜头/配饰
各类 77–98%；例外是场景 57% 和背景 40%——不少人把场景/背景词紧跟画师串写在开头）。

> **有一条跟直觉相反，而且我没有验证过**：镜头取景词（`from below` `close-up`
> `cowboy shot` 这些）在群里的实际位置是**中后段**，排在服装和表情后面
> （只有 10% 的情况排在人数前面）。而「靠前的成分影响力更大」这条又是成立的。
> 两者矛盾——可能是位置对镜头词影响不大，也可能是群里在这上面吃了亏。
> **8/25 的出图实测只测了词组 vs 句子，没测位置**，所以这里只报现状，不给建议。

### 0.4 迭代与密度（旧输出约定恢复）

- **迭代时每轮只改 2–3 处**，说明改了哪几处、各针对什么问题，其余原样保留，
  不整体重写。（扩展的「当前提示词」「上一轮结果」上下文块就是冲着这条来的。）
- **首版默认充实密度**：约 10 个锚点 + 完整句子段落，不给最小骨架；
  上限是不烧图——单 tag 权重不过高、场景物体不超过约 20 个。
- **底部列出不确定的 tag** 及删掉后的兜底方案；没有就不写。
- 构图只说方向（竖/横/超宽/方），不写像素。

## 1. 提示词是功能块的序列

一条 V5 提示词由若干**职能块**顺序拼成。NAI 不认识"块"这个概念——
分块是写作者的组织方式，但它实际影响生成：**靠前的成分影响力大于靠后**。

实测 957 条真提示词：**74% 用空行分段**，空行段数中位 3 段。
官方 12 条示例里 4 条也用空行分段，一段一个职能。**这是最主导的结构手段。**

| 块 | 装什么 | 群里的实际位置 |
|---|---|---|
| **主体锚** | 人数、solo、关键独立物件 | **最前**（领先多数类 77–98%） |
| **场景 / 背景** | 空间结构、物件清单、天气时段 | 中前 |
| **动作** | 姿势、体位、手部动作 | **中后**（排在表情和镜头之后） |
| **关系** | 空间关系、道具归属、运动的进行中状态 | 跟着动作 |
| **镜头** | 取景、视角、机位高低、部位锚定 | **中后**，见 §0.3 的注意事项 |
| **光影** | 主光方向与性质、第二光源、投影 | 中后 |
| **氛围色彩** | 色调、饱和、情绪 | 后 |
| **技法风格** | 上色方式、线条、媒材、复杂度 | 后（76% 排在质量尾之前） |
| **版式与文字** | 分格、贴纸、画面内文字 | 视需要 |
| **质量尾** | 质量词 | **整条的最末尾**，见下 |

不必全有，按画面需要取。
**角色的外貌、服装、配饰、角色名不在这张表里**——它们走角色栏，见 §0.1。

> **质量词只写一组、只放在整条提示词的最末尾，写在句子之后**——不是「tag 段的末尾」，
> 也不要在开头或中段再来一份（统计里头尾各写一遍的是个别人的预设方言，不要学）。
> 332 条既有 tag 又有长句的真提示词里，**最后一次质量词的位置中位在整条 100% 处，
> 79% 落在最后 30%**。用 A 形态（tag 块 + 句子块）写时最容易搞错这一处——
> 把质量词收在第一段 tag 的尾巴上，后面还有三段句子。

「位置」一列是 957 条真提示词的实测两两先后，**不是「应该这么放」**。
只有「人数最前、质量尾最后」两条同时有统计支持和明确理由（人数决定整张图的构成；
质量词不描述内容）。中间那几档的先后差距在 53–70% 之间，属于倾向而非规则。

## 2. 每块两种笔法，判据是「这块内容用哪种说得准」

V5 不在乎某一块写成 tag 还是句子——官方原话是 "Just describe the image in your mind"，
同时又说 "prompting with tags is still fully supported"。
官方 12 条示例从 8 个词到 1215 字符长文都成立。

- **词组笔法**：短词组并列，逗号分隔。可以是 danbooru 规范 tag，也可以不是。
- **句子笔法**：自然语言，现在时或现在进行时，一段一个职能。

**判据**：句子在写**关系**时更准，词组在写**离散事实**时更准。

- 关系＝谁在谁前面、离镜头多近、占画幅多少、光从哪来打在哪、动作停在哪一瞬
- 离散事实＝几个人、几只袜子、机位多高、什么姿势、什么取景

依据是 2026-08-25 的出图实测：3 个 seed 锁死、其余提示词全部固定、只换被测那一块，
共 14 张（锁种子只是取证手段——**正常出图种子一律随机不锁**）。**样本只够支撑「三次都往同一个方向走」，不够给概率**——
逐条的成立次数和局限见文末 §10 附录。这一轮推翻了两条旧判据，也见 §10。

## 3. 必须词组化的（写成句子模型抓不稳）

### 3.1 人数与主体
`1girl` `2girls` `1boy` `1other` `solo` `multiple girls`
多人时人数 tag **只在最开头出现一次**，角色栏里写不带数字的 `girl`/`boy`。

### 3.2 种族体征
"she has cat ears" 不如直接 `cat ears` 稳。
`cat ears` `fox ears` `rabbit ears` `pointy ears` `elf ears` `horns` `cat tail` `fox tail` `wings`

### 3.3 镜头与视角 —— **含机位高低**
`full body` `upper body` `close-up` `cowboy shot` `wide shot` `portrait`
`from below` `from above` `from side` `from behind` `dutch angle` `foreshortening`
`straight on` `three-quarter view` `pov` `profile`

**机位高低必须用 tag，别指望句子。** 3 seed 实测：
`The camera sits low and close…` 这类句子**三次都没压低机位**，全是平视；
换 `from below`（88k posts）**三次全部仰视**。

⚠️ `from below` + `foot focus` + `feet out of frame` 三个一起上是重手——
会把姿势 tag 整个盖过去，人变成近乎躺倒。要低机位又保姿势，**只留 `from below`**。

**「占多大」仍归句子**（见 4.4）：机位归 tag，占画幅比例归句子。

### 3.4 姿势与体位
`sitting` `standing` `lying` `kneeling` `squatting` `sitting sideways` `leg up`
`knees up` `crossed legs` `arm support` `head rest` `hand on own cheek`
`arms up` `legs up` `hugging own legs` `on side` `on back` `on stomach`

3 seed 实测（其余全固定，只换姿势块）：

| 写法 | 结果 |
|---|---|
| 句子：`She sits sideways on the windowsill with one knee drawn up…` | **3/3 失败** |
| 词组：`sitting, sideways, leg up, arm support, head rest, hand on own cheek` | **3/3 成功** |

**失败方式值得记住：不是画错姿势，是把姿势画糊。**
三次都出现多余的腿、接不上的胯——句子把肢体关系描述得越细，
模型越容易把每个从句各画一遍。这是最高频的失败模式。

### 3.5 服装状态 —— **先查语义再用词**
danbooru 服装 tag 里，**「一种衣服」和「一种穿法」长得很像，选错会静默把衣服换掉**。

| tag | post | 真实语义 | 常被误当成 |
|---|---|---|---|
| `loose socks` | 14k | **堆堆袜**，一种粗针棉袜 | ❌「丝袜堆下来」 |
| `single thighhigh` | 62k | **只穿了一只**，另一腿光着 | ❌「一只滑下来了」 |
| `uneven legwear` | 16k | 两腿袜子**不一样** | ⚠ 语义对，但实测**单独写推不动**（0/3） |
| `asymmetrical legwear` | 41k | 同上，更高频 | 同上 |
| `thighhighs pull` | 1.9k | 拉扯丝袜的**动作** | 太弱，别用 |

写 `white thighhighs, loose socks` 想要「白丝滑下来」，拿到的是**粗针堆堆袜**，
形制被换掉且不报错。

**规则：服装状态词用之前查它的中文释义，别按英文字面推。**
这类词的误伤是**换衣服**，不是「效果弱一点」。

**形制归 tag，不对称与位置归句子**（2026-08-27 重测 9 张：`white thighhighs`
钉形制 9/9；`uneven legwear` 单独写不对称 0/3；**含状态句子的 6/6 全部做出不对称**，
位置「堆在哪」句子能指定但精度不稳。详见 §10 附录）。
> `white thighhighs, uneven legwear.`
> "One thighhigh has slipped down to bunch just below the knee."

### 3.6 部位锚定（`X focus` 家族）
控制「重点在哪个部位」最直接的手段，但各词可靠度差别极大：

| 强度 | 词 |
|---|---|
| 正常用 | `ass focus` 31.8k · `foot focus` 27.1k · `hip focus` 15.5k |
| 偏弱 | `eye focus` 3.1k · `breast focus` 2.6k（**单数**）· `back focus` 2.2k · `hand focus` 1.9k · `armpit focus` 1.1k |
| 太弱，改句子 | `navel focus` 528 · `thigh focus` 460 · **`leg focus` 266** |

**一个反常**：想强调腿时**没有好用的锚定词**，必须靠机位 + 句子；
而脚有 `foot focus` 27k，是下半身唯一硬的抓手。

`sharp focus` / `soft focus` / `out of focus` 是景深词，不是部位锚定，别混。

### 3.7 IP 与角色名 —— **名字 + 简单引导词，不要枚举外观**

写规范名 + 作品名（`archetto (arknights), arknights`），放进那个角色的角色栏。
**只在确实认得时写**——冷门角色写了模型也不认，反而干扰。

**关键在后面那半：角色 tag 本身就带着这个角色的全套外观和常见服装。**
你在同一格里再补的发色、发型、袜子，**补对了是冗余，补错了是跟角色 tag 打架**。
而「印象里她是什么样」非常不可靠。

**正确做法：名字 + 一两个笼统的引导词，让角色 tag 自己去匹配具体设计。**

> `chihaya_anon, school uniform` → 自动落到**羽丘校服**
> （`chihaya_anon + school_uniform` 3901 张，其中 `haneoka_school_uniform` 占 **86%**）
>
> `gotoh_hitori, track jacket` → 自动落到她那件粉色运动外套（6642 张，比她的校服还高）

**不要**写成 `chihaya_anon, school uniform, sailor collar, pleated skirt, black ribbon, loose socks`——
`school uniform` 已经把羽丘校服带出来了，后面那串**要么是废话，要么是错的**：
枚举得越细，错的机会越多，而且一个词错了就跟角色 tag 顶上。

**判断标准很简单：这个角色穿的是不是他的常规设定？**

- **是**（默认情况）→ 名字 + 作品名 + 一个笼统场合词就够了。
  `takamatsu_tomori, bang_dream!_it's_mygo!!!!!, school uniform` —— 停在这里。
- **不是**（换装、泳装、私服、alternate costume）→ 才需要写具体的服装词，
  而且要写成一个**成套的说法**（`swimsuit` / `casual clothes` / `maid`），
  不是拆成领子、裙子、丝带一件件列。

同一条也适用于外观：**没换发色就不用写发色，没换发型就不用写发型。**

**凭印象补属性的实测错误率**（2026-08-25，一次多人产出里补了 14 个属性，错 9 个）：

| 写的 | 该角色实际的共现率 | 实际是 |
|---|---|---|
| `ijichi_nijika` + `green hair` | **0.3%** | `blonde hair` 89% |
| `ijichi_nijika` + `twintails` | 1.5% | `side ponytail` 69% |
| `gotoh_hitori` + `hime cut` | **0.1%** | — |
| `nagasaki_soyo` + `blonde hair` | 2% | `brown hair` 76% |
| `chihaya_anon` + `loose socks` | **0.13%** | `kneehighs` |
| `takamatsu_tomori` + `white hair` | 17% | `grey hair` 72% |
| `kita_ikuyo` + `orange hair` | **0.7%** | `red hair` 89% |
| `shiina_taki` + `dark green hair` | **0 张** | — |
| `yamada_ryo` + `half-closed eyes` | 0.9% | — |

**三条规则**：

1. **不确定就只写名字 + 作品名 + 一两个笼统引导词**（`school uniform` / `casual clothes` /
   `track jacket` / `swimsuit`）。少写不会错，写错会打架。
2. **`search_tags` 在这里帮不上忙。** 它能告诉你一个写法存不存在、有多少 post，
   **但查不了「这个角色和这个属性一起出现过多少次」**（它是逐个 tag 查的）。
   所以「先查一下再写」在运行时做不到——**能做的只有第 1 条：少写。**
3. **故意改设定**（换装、换发色）是另一回事——那要加权重压过原设定，并且明说是改动。

**外观之外的事（职能、归属、相对位置）角色 tag 一概不带，规则在 §4.2。**
那半才是多人版权图最容易出错的地方——外观交给 tag 就不会错，
职能没有任何东西替你兜底。

### 3.9 互斥组：这几类各只能挑一个

同一组里挑两个以上，模型会在两个矛盾指令之间摇摆，通常是两个都做不准。

| 组 | 取值 | 例外 |
|---|---|---|
| **视线方向** | `looking at viewer` · `looking to the side` · `looking up` · `looking down` · `looking away` · `looking at another` | `looking back`（回头）和 `closed eyes`（闭眼）**不是方向**，可以跟方向叠 |
| **取景距离** | `close-up` · `portrait` · `upper body` · `cowboy shot` · `full body` | `wide shot` 说的是镜头退多远，可以跟 `full body` 叠 |
| **背景形态** | `simple background` · `blurry background` · `white background` · `detailed background` · `transparent background` · `dark background` | 无 |
| **体位** | `sitting` · `standing` · `lying` · `kneeling` · `squatting` | **多角色例外**——一人站一人蹲时两个都要写，靠句子说清谁是谁 |

实测 254 条有视线词的提示词里 **20% 写了不止一个方向**
（`looking down` + `looking up` 这种直接矛盾的也有）；
415 条有取景词的里 **22% 写了不止一个距离**。这是群里很常见的一个失误，不是好写法。

**顺带一个纯浪费的**：`close up` 和 `close-up` 是同一个词的两种写法，
语料里有 18 条把两个都写上了。挑一个就行。

## 4. 必须写成句子的（tag 体系没有对应词，或有词也说不准）

### 4.1 空间关系与归属
谁在谁前面、谁离镜头更近、道具属于谁。**多人防串味的主要手段。**
> "Character 1 stands at the left side of the room beneath a red safelight.
> Character 2 stands farther back on the right side beside an enlarger.
> The umbrella belongs only to Character 2."

> **角色栏的编号顺序不一定由你定。** 用户在自己的角色词库里存过的角色，
> 只要名字出现在需求里，前端就按**名字在需求文本里first出现的先后**
> 直接指派 `Character 1 / 2 / 3…`，并把那个角色的外观串塞进对应格。
> 这种时候你收到的上下文里会有「【用户点名的角色】Character 1 = 某某：…」，
> **照它的编号写，不要自己重排**。没有这段的时候编号才由你定。

**编号必须跟角色栏的名字一模一样**：角色栏叫 `Character 1` / `Character 2`，
句子里就写 `Character 1` / `Character 2`。**不要写 `Character A / B`**——
那样句子和角色栏对不上，模型没法把「站左边」和「戴草帽的那个」绑起来。
实测语料里有 13 条犯了这个错（句子写 A/B，角色栏是编号的），
运行环境的口径也是「按 Character 1 到 Character N 顺序排列」。

### 4.2 职能与归属 —— 角色 tag 带不了的那半，**没把握就别分配**

§3.7 讲的是「角色 tag 自带外观，所以不要枚举」。这一条是它的另一半：

| 角色 tag **带**的 | 角色 tag **不带**的 |
|---|---|
| 发色 · 发型 · 眼睛 · 体型 · 常规服装 | **群体里的职能**（谁弹贝斯、谁是队长） |
| | **归属关系**（东西是谁的、谁是谁的姐姐） |
| | **相对位置**（谁站中间、谁最高） |

**右边这一列正好等于「你不得不写进主提示词句子里的那部分」。**
外观有 tag 兜底，写错了也会被角色 tag 拉回来；
职能没有任何东西兜底，**你写什么就是什么**。

**凭印象分配职能的实测**：2026-08-25 的 MyGO 五人图，`nagasaki_soyo` 写成弹电吉他、
`kaname_raana` 写成弹贝斯——**两人写反**，出图就是五个人拿着不对的乐器。
外观一处没串，坏就坏在这一句。

#### 运行时**查不到**职能 —— 所以默认就是不指定

`search_tags` 能给的只有三样：**这个写法存不存在 · post 量 · 中文名**。
它查的是 danbooru 的 `/tags.json`，**不返回 wiki 简介**；
本地词典里那个「中文释义」是 tag 名的译名（`nagasaki_soyo` → 长崎爽世），不是人物介绍。
而且它是**逐个 tag 查**的，两个 tag 求交（「这个角色和贝斯一起出现过多少次」）**做不到**。

所以：**职能、归属、相对位置这三类，你在运行时没有任何办法核实。**

> 以上说的是只有 `search_tags` 的运行环境。**有广域网络检索的环境**
> （网页聊天、带浏览器的 agent）不受此限——按构思「版权角色先查档案」节
> 先查再写：查实了职能就可以放心分配；查不了仍按本节保守规则。
唯一的依据是你自己的记忆，而记忆在这件事上实测是会错的（上面 MyGO 那次）。

**结论就一句：拿不准就别分配。** 判断拿不准的标准——

> **这件事你会不会写进这个角色的一句话简介里？**
> 「她是鼓手」会 → 可以写。「她大概是弹贝斯的那个吧」不会 → 不要写。

人越多越容易记混（五人乐队里排第四第五的那两个），**四个人以上一律倾向于不分配。**

**别拿 `search_tags` 去找职能。** 它回答的是「这个写法存不存在、有多少张图」，
不是「这几个人里谁打鼓」——查 `drummer` / `鼓手` 只会拿回那个 tag 自己的 post 量，
跟角色没有关联。而工具调用只有 4 步，白查一轮就少一轮。

#### 不要因为「想查证」就卡住

**别在回复里写「我先查一下这几个角色」，也别因为拿不准就停下来反问用户。**
拿不准的处理方式是下面那条「不指定」，不是不给结果。
（实测：漏掉这句时，模型回了一句「我先查证四个角色的信息」然后什么都没给。）

#### 分不出来就不要指定

> ✅ "Each member stands at her own instrument position."
> ❌ "Character 3 plays bass while Character 4 plays electric guitar."

少写一句不会错，写反了整张图都怪。**而且「不写」不等于「随机」**——
模型学的是同一批共现，把场合写清楚（`band performance, on stage, live house`）
它会按自己的先验去分配；你写错的时候才是在跟这个先验对着干。
（后半句是推理，**没有单独出图验证过**。）

反过来，**确实有把握时要写死归属**（那种写进一句话简介都不会错的）：
> "The microphone belongs only to Character 1."

归属句本来就是多人防串味的主要手段，**该写的时候别省**——
要避免的是「猜一个分配」，不是「避免写归属」。

#### 这一条不只对版权角色

多人共用一件道具时（一把伞、一份便当、一只猫），归属句本来就是防串味的主要手段（§4.1）。
版权角色只是多了个「查得到正确答案」的前提；**原创角色的归属由你定**，
那更要在句子里说死——没有任何先验能替你兜底。

### 4.3 透视关系（**不含机位高低**）
焦距感、前后压缩、什么离镜头近。用对比句式最有效。
> "One foot is very close to the lens while the rest of her body rapidly recedes into depth."

### 4.4 占画幅多少
tag 完全说不了的一类。想强调腿部就靠这个。
> `from below, white thighhighs, uneven legwear.`
> "Her legs dominate the lower half of the frame, and one thighhigh has slipped down
> to bunch just below the knee."

### 4.5 运动的「进行中」状态
tag 只能说 `running`，说不出停在哪一瞬、衣物头发怎么响应。
> "Her body is caught halfway through a natural running motion. Her clothing and hair
> react to the movement and wind rather than hanging motionless."

**否定句排除静止感很有效**（"rather than hanging motionless"）。

### 4.6 光影叙事
主光源 + 第二光源 + 投影形状。
> "The red safelight dominates the room, but a thin strip of neutral light enters beneath
> the closed door and produces a second subtle lighting direction."

⚠️ 光线**方向**只有 2/3 成立（弱于姿势和机位），要保光位就配一个方向 tag 兜底。

### 4.7 场景物件的整体性
清单式罗列，然后补一句整体性要求，防止糊成抽象纹理。**这条 3/3 成立。**
> "The darkroom contains several separate chemical trays, bottles, measuring cylinders,
> clips, hanging prints, an enlarger, a timer, shelves and a small sink.
> The equipment should remain recognizable and spatially coherent rather than dissolving
> into abstract machinery."

### 4.8 句法约定
- 主语：单人 `The character`；多人 `Character 1 / Character 2 / Character 3`——**跟角色栏同名**
- 时态：现在时或现在进行时
- 一段一个职能，段间空行
- **关键独立物件仍要拎出来单独做 tag 放前部**，别埋进句子
  （`transparent umbrella, wooden bench` 优于 "holding a transparent umbrella on a wooden bench"）
- **叙事段不要整段包在引号里**。引号在提示词里的既定语义是「要画进图里的文字」
  （画中文字的写法就是引号＋载体，见 §4 分格配套条与排查表）；把叙事句包进引号，
  是在冒模型把整句当画面文字渲染的风险。957 条真提示词里包长段引号的只有 19 条（2%）。
  句子直接写。

### 4.9 多人交互：先定施受，再找锚点

多人图最容易写空的不是外观，是**人和人之间发生了什么**。
「三个人在野餐」是三个各自独立的人，不是一张有交互的图。

#### 先把每个人放进一个格子

给每个角色定三样，缺一样这个人就会变成背景板：

| | 问什么 | 例 |
|---|---|---|
| **动作** | 她在**对谁**做什么？ | Character 1 递杯子**给 Character 2** |
| **承受** | 她**被**谁做了什么？ | Character 2 的手被 Character 1 压住 |
| **参与度** | 她在这件事里是**施加 / 承受 / 旁观 / 完全不在场**？ | Character 3 低头看手机，不参与 |

**「完全不在场」也是一种参与度**，而且往往比让三个人都热闹更有意思——
一个人置身事外会把另外两个人的关系衬出来。

#### 接触点必须有主人

每一个接触、每一件共用的道具，都要说清**是谁的手、碰到谁的哪里**：

> ✅ "Character 1 presses her palm down on the back of Character 2's hand."
> ❌ "Their hands are touching."（谁的手？碰哪儿？模型自己编）

同一小块画面里出现三只手时，补一句**「每只手都清楚地连在自己主人身上」**——
这是多人图最常见的解剖崩坏点。

#### 然后才去找锚点（这一步是实现，不是查错）

构思出来的画面里，**哪几样是必须钉死的离散事实**？为每一样去词典里找 tag。
找到了就用词组钉住，这是把想法变成图的第一步；**找不到才退回句子**。

实测一次（三人递接场景）：

| 构思里的那一下 | 找到的锚点 | 结果 |
|---|---|---|
| 手是张开伸出去的 | `outstretched hand` 32.4k | ✅ 钉住了 |
| 手里有个杯子 | `holding cup` 110k | ✅ |
| 一个人压着另一个人的手 | `hand on another's hand` 2.9k（弱） | ⚠️ 弱，要配句子 |
| 「伸到一半没接住」 | 没有 tag，这是关系 | → 句子 |

**词典没有规律，别靠语感判断存不存在。** 同一批里
`outstretched hand` 32421 而 `raised hand` **0**、`hand grab` 6159 而 `arm grab` **0**、
`pushing away` 1327 而 `reaching out` **0**。凭直觉列的 34 个词有 **20 个是 0 张**。

> 但这不等于「不确定就别写」——**写进句子里怎么写都行**，自然语言不需要 tag 存在。
> 要查的只是「我想钉死的这一下，有没有现成的词能钉」。找不到不是失败，是改用句子。

#### 施受方向用前缀钉在角色栏

V5 认三个方向前缀，**写在角色栏里**（不是主提示词）：

```
source#{动作}   这个角色在发起
target#{动作}   这个角色在承受
mutual#{动作}   两人互相做同一个动作
```

只有这三个，前缀表示**动作方向**，不是角色身份 ——
`female#hug` `char1#hug` `left#hug` 都无效。

群里 作者B 的实际写法比这更细，**动作和部位各写一条**，视线另用 `looking at target`：

```
Character 1: <角色名>, source#teasing, source#touching face, smirk, looking at target
Character 2: <角色名>, target#teased,  target#face touched, blush, embarrassed
```

**前缀不是强制的，它跟句子是分工不是二选一**——还是 §2 那条判据：

| 前缀（词组笔法） | 句子笔法 |
|---|---|
| **谁是施加方** —— 离散事实 | **这个动作长什么样、停在哪一瞬** —— 关系 |
| `source#pinning down` | "her fingertips have only just touched the rim and have not closed around it yet" |

**什么时候值得加前缀**：「谁对谁」本身容易错的时候——三人以上、接触密集、
或者两人动作互相对称（都伸着手，谁递谁接看不出来）。

#### 前缀能做到的三件事（5 张实测）

**① `target#` 只绑方向，不绑「气势」。** 承受方可以是画面上更主动的那个：

> Character 1: `source#piggyback, looking down, tired, closed mouth` ← 背人的，闷头走
> Character 2: `target#piggyback, pointing, open mouth, excited` ← 被背的，指着前方在说话

实测出来正是这样——背的人低头闭嘴，被背的人手臂伸直在指。
**前缀管归属，表情和动作 tag 管气质，两层互不干涉。**

**② 同一个角色栏里可以同时挂 `target#` 和 `source#`**，两个方向同时生效。
A→B→C 的链式交互就是这么写的：

> Character 1: `source#covering another's eyes`
> Character 2: `target#eyes covered, source#headpat`　← 一个人两个方向
> Character 3: `target#headpat`

出图：黑发从背后捂住粉发的眼睛，粉发眼睛被捂着还在笑、**同时她自己的手按在棕发头上**。

**③ `mutual#` 产生真对称**，看不出谁发起，姿态镜像：

> Character 1 / Character 2 都写 `mutual#forehead-to-forehead, mutual#eye contact`

#### 第三人：动作也要进前缀，只写句子会被吃掉

6 张实测的规律：第三人（主交互之外的那个）**光靠句子指挥不动**——
主角的交互吃掉了模型的注意力。

| 给第三人写的 | 结果 |
|---|---|
| 句子写「趁两人较劲时把西瓜端走」，角色栏只有 `holding food` | ❌ 变成纯旁观 |
| 同一件事写成 `source#taking food, source#food theft, smug` | ✅ **真的拿到手正在吃** |
| 只要「在场且不参与」（`crossed arms, looking at another`） | ✅ 成 |

**`source#` 对物体也有效**——没有明确的 target 角色照样成立（`source#taking food`）。
所以第三人的规则就一条：她做什么，就把那个动作写进她自己的前缀或 tag，
句子只用来补「她跟主交互的关系」。

#### 相对位置和占画幅：交给 Custom position 控件，文字写不动

「谁离镜头近、谁占画幅大、谁在远处缩小」**用文字写了两次都没执行**，
换 NAI 的 **Character Prompts → Position → Custom** 一次成功：

- 点位的 **Y 坐标会被解释成深度**：下 = 近（可以只露局部、占最大），上 = 远（明显缩小）
- 用法：**控件定层次，句子描述层次**，两个一起上——
  句子写 "Character 1 is closest to the camera, cropped at the waist by the frame
  edge… Character 3 is far up the street, clearly smaller in the frame"，
  点位拖成 左下 / 中 / 右上
- 这正好接上构思层「监督」那步的要求（近景只露局部、中景主动作、远处明显缩小）——
  **分镜里的前中后景，落地时走控件不走文字**

（输出提示词文本时点不了控件——那就把点位建议**单独写一行**给用户：
「Position 建议切 Custom：Character 1 左下、Character 2 中、Character 3 右上」。）

#### ⚠️ 已知做不到的：`Character N` 钉不住职能和位置

2026-08-26 实测，同一张图里：

| | 结果 |
|---|---|
| 外观归属（谁穿什么、谁什么发色） | **准** —— 三个人零串色 |
| 职能归属（谁递给谁）**写在句子里** | **错** —— 写的是 1 递给 2，出来是 1 递给 3 |
| 同一件事**改用 `source#`/`target#` 写在角色栏** | **对** —— 施受完全正确 |
| 相对位置 / 占画幅 | 文字不行，**Custom position 控件一次成功**（见上一节） |
| 人数 | **多出一个** —— 写 `3girls`，出了 4 个人 |

**所以多人交互目前只能保证「动作本身画对」，保证不了「这个动作属于哪一号」。**
在这条解决之前：

- 让交互**只发生在两个人之间**，第三个人明确置身事外（错配的空间就小）
- 用**外观**而不是编号来指认：写 "the girl in the beige coat hands the cup to
  the girl with headphones" 比写 "Character 1 hands it to Character 3" 更可能对
  ——外观绑定是准的，编号绑定不准，**那就用准的那个去指**
- 人数写了还是可能多出来，UC 里别指望 `extra characters` 兜底（见下）

#### ⚠️ 单人的 UC 预设不能直接用在多人图上

群里常用的那条 UC 里有 `2::little dolls, extra characters, ..., ::`——
**那是给 solo 图写的**。三个人的图带着它，权重 2 的「多余角色」会跟你的 `3girls` 打架。
多人图要先把这一段拿掉。


### 4.10 漫画与分格：先声明版式，再逐格写内容

两位真画漫画的作者（作者E 49 条 chibi 漫画 · 作者F 群像分格）写法高度一致，
方法就三步：

**① 第一句话声明版式**——几格、怎么排、有没有边框，后面所有内容服从它：

> "A four-panel manga-style scene …"（顺序四格）
> "A 3x3 grid of nine headshot portraits …"（九宫格）
> "two-panel comic, one large main illustration and one small rectangular inset
> in the lower-right corner, white panel borders"（主图 + 插入格，作者F的常用结构）

版式声明基本靠**句子**；tag 只有 `comic` / `4koma` / `multiple views` / `inset`
这几个粗粒度的（见 §3.8），格数和排布 tag 说不了。

**② 逐格一条，每条带方位锚**——bullet 或编号都行，方位写死：

> · Top-left (Joy): bright yellow background, wide smile, happy squinted eyes.
> · Bottom-center (Drooling daze): pale pink background, blank stare …
>
> 1. Front half-body portrait (center-left): …
> 3. Back view (bottom-right): …

每格自己的内容自己一条（表情 / 动作 / 底色），**格与格不共享句子**。

**③ 给格子之间一个联系装置**，防止散成互不相干的小图：

| 装置 | 例 |
|---|---|
| **主锚格** | 九宫格中央放一张无表情的脸当锚，其余八格围绕它 |
| **主次结构** | 一大一小：主图演戏，inset 放一格反应特写（作者F的模式） |
| **贯穿系统** | 每格底色对应情绪；四季各一格各一个色调；线索板上的红线连所有条目 |
| **收尾句** | 最后一段重申「格子等大、排列整齐、焦点只在哪」 |

**配套的几条**：

- **角色栏只放一份外观，跨格复用**——同一个角色在多格里反复出现，
  外观进角色栏是防跨格漂移的主要手段（作者E 49/49 都用了角色栏）
- **画风上做减法**：作者E整套是 `minimalism` + `1.3::no lineart::` + `2::chibi, chibi only::`，
  作者F是 `1.2::rough sketch::` + `crayon_(medium)` 手绘媒材——
  **多格塞的东西多，单格画风越简越不糊**
- 画中文字照老规矩：引号 + 载体（"a small paper tag reads「…」"）
- **一个可偷的创意**：把版式做成**画中实物**——侦探线索板、相册页、桌上摊开的拍立得，
  格子变成钉在板上的照片，天然解释了「为什么一张图里有很多小图」（作者E 3 条这么干）


## 5. 三种成品形态

三种形态就是笔法在块上的不同分配，都成立：

| 形态 | 分配 | 适合 |
|---|---|---|
| **A 词组块 + 句子块** | 主体锚/镜头/姿势用词组，关系/场景/光影用句子 | **默认**，可控性与表现力平衡最好 |
| **B 词组织进句子** | 混在同一行逗号并列 | 内容零散、有具体 UI/文字要求时 |
| **C 纯句子** | 全部自然语言 | 画面是完整场景叙事，或写风格调性 |

官方各有实例：A 见示例 #1（空行分十段），B 见 #4，C 见 #2 和 #5。

## 6. 质量词与负面词

**质量词**：`very aesthetic` `masterpiece` `no text` **由前端画质预设自动附加**，
自己不必重复，除非要覆盖预设。要更高完成度加 `best quality` `amazing quality`
`absurdres` `ultra detailed`。密度：普通图 `high complexity`，海报/大场景 `ultra complexity`。

**UC**：默认预设留着就行，**不用重复写**。
> 那批 95–99% 出现率的词是前端预设带进来的，**不是群体共识**，别当统计发现引用。
> 反证：官方 12 条示例 **12/12 手写 UC，一条都没用默认预设**。

真正要写的是**针对这张图的排除项**：`nsfw`（要 SFW）· `muted color, pale color, flat color`（要浓色）
· `oiled skin, shiny skin`（不要油光）。
画面里明确不想要的具体元素，**直接负权重写进正文更准**，比堆进 UC 有效。

## 8. 排查

| 症状 | 处理 |
|---|---|
| **姿势画糊、多出一条腿** | **姿势那段写成句子了**。改 tag（`sitting, leg up, arm support, head rest`）。最高频失败模式 |
| **机位压不低** | 句子推不动机位，加 `from below`。三个镜头 tag 别一起上，会盖掉姿势 |
| **袜子/手套形制或数量不对** | 先查中文释义。`loose socks` 是堆堆袜、`single thighhigh` 是只穿一只，都会静默换衣服。要「一只拉起一只滑下」**用句子写状态**（`uneven legwear` 单独写推不动，实测 0/3） |
| **整张图变成一片纹理／泥浆** | 画师名或 tag **以数字结尾**又紧跟 `::`——`na_tarapisu153::` 会被解析成权重 **153**，整条提示词被炸掉。写成 `na_tarapisu153 ::` 或 `na_tarapisu153, ::`（数字和 `::` 之间要有东西） |
| tag 被忽略 | 提权重 / 移到前部 / 拆成独立 tag / 改用整句 |
| 画面平、缺层次 | 补光影层（主光方向 + 投影形状）；色彩层次差加主题色 |
| 色调不符 | 加主题色或 `limited palette`；色彩词前移 |
| 逆光面部过暗 | `-2::backlighting::` 或补 `front lighting` / `face lighting` |
| 角色白背景虚空 | `-1::simple background::` + 明确写场景 |
| 多角色串味 | 句子写死归属 + 编号对应画布定位 + 检查人数 tag 位置 |
| 动作僵硬 | 句子写进行中的状态 + 衣物头发被动响应。**但姿势本身用 tag** |
| 场景糊成抽象物 | 清单后补整体性要求句 |
| 透视不对 | 机位用 tag，前后压缩用对比句式 |
| 想强调腿但出不来 | 别堆 `thighhighs, bare legs`，也别用 `leg focus`（266 太弱）。`from below` 压机位 + 句子写占画幅；要到脚就 `foot focus` |
| 文字不出/出错 | 引号包裹 + 句子描述位置样式；别手写 `Text:` 块 |
| 出来太"通用"没个性 | 主力档挑太多了。往常见/可选档挪 |
| 固定物体始终画不对 | 模型知识盲区，换构图思路，别堆 tag |

## 9. 写完对照

每条后面是它的依据强度。**前四条有实测或统计支撑，后四条只是内部一致性检查。**

| 检查 | 依据 |
|---|---|
| 姿势那块是词组，不是句子 | 出图实测 4/4（跨两条画师串） |
| 机位高低用 tag，不是句子 | 出图实测 3/3 成立 vs 3/3 失败 |
| 角色外貌 / 服装 / 角色名在角色栏，不在主提示词 | 445 条实测的分工：发型 52% vs 9%、服装 56% vs 30% |
| 人数 tag 在最前且只出现一次 | 领先多数类 77–98%（n=298–491） |

### 姿势那条的失败方式值得单独记

句子版失败**不是画错姿势，是把姿势画糊**：

- seed 1111：坐到书桌而非窗台，腿部能数出三段结构
- seed 2222：变成两腿摊开，不是抱膝
- seed 3333：瘫坐伸腿，胯部结构混乱
- 换 作者B 串重测：**曲起的那条腿整个没画出来**，大腿形状在上面断掉

> 句子把肢体关系描述得越细，模型越容易**把每个从句各画一遍**。
>
> 两条画师串的画风差异很大（作者B 是平涂 + 清晰线条，A1 ycb 是厚涂笔触），
> 但**失败模式一模一样**。这说明它是模型对「长从句描述肢体关系」的处理方式问题，
> 不是某条画师串的副作用。

### 服装那条为什么作废过一次

原本要测「服装状态用句子还是词组」。**词组组选错了词，对照不成立。**

12 张图里袜子全出成了**粗针堆堆袜**，不是丝袜。原因：

| tag | post | 真实语义 | 我当时以为的 |
|---|---|---|---|
| `loose socks` | 14k | **堆堆袜**（一种衣服） | ❌「丝袜堆下来」（一种状态） |
| `single thighhigh` | 62k | **只穿了一只**，另一腿光着 | ❌「一只滑下来了」 |
| `uneven legwear` | 16k | 两腿袜子**不一样** | ✅ 这才是要的 |
| `asymmetrical legwear` | 41k | 同上，更高频 | ✅ |

所以那组词不只指定了数量，还**把衣服换掉了**。
seed 1111 那张「一条腿有袜子一条腿光着」，是 `single thighhigh` 忠实执行的结果。

换成 `white thighhighs, uneven legwear` 重跑，**形制立刻正确**（光滑丝袜），
交叉验证的两张也都正确——确认 `loose socks` 就是形制跑偏的原因。

**留下的教训（这条比原本要测的结论更有价值）**：

> 服装状态词写之前**查它的中文释义**，不要按英文字面推语义。
> 这类词的误伤是**换衣服**，不是「效果弱一点」，而且**不报错**。

**2026-08-27 已用修正词重测**（`naitrace/tests/20260827-服装状态对照.md`，9 张）：
C1 纯词组（`white thighhighs, uneven legwear`）不对称 **0/3**；
C2 纯句子与 C3 混合 **6/6 全部做出不对称**；「堆在哪」句子能指定但精度不稳
（明确堆膝下 1/6、堆脚踝 2/6、整只脱掉 1/6）；完整合取只有混合版中了一张。
**改判后的建议就是 §3.5 现行条款**：词组只钉形制，不对称与位置全部交给句子。
与「姿势/机位归词组」互补成对。

### 这批测试自身的局限（必须一起读）

- **每格只有 3 个样本**（服装那格只有 2 个）。只够支撑「方向一致」，**不够给概率**。
  「3/3」不等于「100% 成立」，只等于「三次都往同一个方向走」。
- **四个版本共用同一个场景**（窗台 / 猫娘 / 书房）。**换题材不保证同样成立。**
- 判读是肉眼看缩放后的截图，**没有像素级核对**。
- **没有测混合写法**——「姿势词组 + 姿势句子同时写」很可能才是最优解，但没数据。
- 光影方向那条 2/3，样本太少，**不该当成「句子推得动光位」的证据**，
  也不该当成推不动的证据。
